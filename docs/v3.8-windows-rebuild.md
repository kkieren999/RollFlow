# V3.8 Windows rebuild — website-first package

Source of truth: public main commit bbb40b56b2d6c70b660ff894d59db8b7cb250298, copied exactly into app/training. The existing Windows package contained this complete website but its default launcher opened the older protected Django interface instead. The old protected index was 412,570 bytes; the full website is 859,521 bytes.

Start RollFlow.cmd now launches the complete website on loopback, offline, with its 13 fictional identities, role-based navigation, attendance, timetable, class/student tools, workforce, support and reporting demonstrations. No database installation is needed for this mode. It is exactly the public website, including its limitations; browser storage and credentials are not secure authentication. The same fixed training origin (127.0.0.1:18086) preserves existing training browser storage. It cannot read or change the protected database.

Protected Workspace.cmd offers independent fresh database setup (%LOCALAPPDATA%/RollFlow-V38-Fresh-Staging, 18087/55438) or the existing protected database (18085/55437). The old instance is never reset or silently upgraded. Existing database migration uses the existing backup-first command. Keep prior binaries in place. Fresh mode refuses an existing state directory. Protected mode retains server-authenticated permissions, imported OneSchool data and the V3.7 access grants; it is not yet operationally feature-equivalent to the full training UI. Do not put real school data into either staging mode.

## Remaining protected functionality
The full public UI includes browser-local workflows not yet connected to Django/PostgreSQL: attendance submission/corrections, movements, seating/class lists, observations/tasks/referrals/follow-ups, workforce and relief workflows, approvals, duties/calendar exceptions, reports and configurable role templates. Do not point the browser-local frontend at protected school data or present simulated actions as secure school functionality. Port workflows individually with server-side scope checks, transactional persistence, regression tests and ICT approval.
