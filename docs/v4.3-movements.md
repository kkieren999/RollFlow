# V4.3 Student Movements and Services — fictional staging

Migration 0020 creates MovementDestination, StudentMovement and MovementEvent. No prior data deleted. School staff issue a pass from their current verified lesson/roster (including valid relief allocation); active destination required, server timestamps and due time from configured duration. Exactly one open movement per student, including across days. No auto return at bell, no GPS or inferred location; attendance unchanged. Destination and check-in policy copied at issue; archive prevents new issue, existing passes remain actionable. No free text notes or medical diagnoses. No destinations seeded or permissions auto-granted.

State machine: outbound -> arrived -> returning -> returned for staffed services. Unstaffed destination: outbound -> returned. Reception can confirm arrival and release only for granted destination ID; issuer confirms classroom return. Admin can act as reception or record administrative closure with structured reason (not confirmed return). Monitor is read-only school-wide; teacher views own issued records, reception only its destination's staffed passes; no role-name authority. Source publication/stable student identity verified; changed student ID masks name and blocks routine transition, admin may close without claiming return. Existing open passes remain visible after republish/archive; historical records retain original source and issuer. Revision tokens, atomic row locks, unique open constraint, audit and CSRF. Date-select closed history, all open passes including prior dates; overdue means due time passed, not actual student location.

Capabilities: movement_monitor school only; movement_receive destination only. New grants/templates need explicit administrator review. Existing grants not widened. Destination scope uses stable positive numeric ID; inactive destination cannot receive new grants but existing grant can resolve its open passes. Admin creates/archives destinations; no deletion/rename. Existing grants can be revoked/expired through V4.0 UI.

Remaining: full protected browser E2E across devices, concurrency/load and recovery drills, escalation notifications, student-centric timeline across all approved staff interactions, authorised non-class departures/late arrival/early exit, explicit duty handovers when original issuer unavailable, school-approved destination policy and retention, confidential health/guidance case management (not in pass log), approved OneSchool workflows/SSO/MFA. Staging only; no production approval.

Scoped per-student filtering on movement register uses internal student key and existing authorised queryset; does not grant directory access. Regression tests cover exact staffed/un-staffed transitions, direct URL/POST access, stale revisions, duplicate passes, current lesson and roster checks, grant revocation, archive, identity change, administrative closure, overdue carryover and CSRF. Full CI pending.
