## Added reliability gates
- Django fault injection verifies attendance and movement history write failures roll back the primary record and audit, with a clean retry.
- PostgreSQL transaction tests use independent authenticated clients and thread-local database connections with bounded lock/statement timeouts. Test duplicate movement issue and reception, duplicate acknowledgement, independent teachers plus duplicate roll submission, and mutually exclusive school closure versus attendance submission. SQLite explicitly skips these concurrency tests; it does not establish PostgreSQL concurrency.
- Native Linux CI seeds fictional records and verifies attendance revisions and marks, movement history, private notices and session invalidation on restore, while confirming original state remains intact. Existing Windows student/archive restore and installed browser suites remain required.
- Strict manifest verification rejects unexpected symlinks and case-colliding files. Restore verifies dump structure with pg_restore --list before creating new state; checksum failure and invalid dump preflight are regression-tested. This is not proof of authenticity, nor full semantic validation of untrusted dumps.
- Windows CI verifies installed metadata version and checked-out commit for both packages; preserves package hashes, offline smoke, installed multi-role browser and readiness checks. JS syntax checks cover protected scripts.
- RC2.7 Django and PostgreSQL/native jobs passed before this build. RC2.7 installed Windows evidence still pending. RC2.8 exact-commit tests must pass; test additions are not themselves evidence of passing tests.
