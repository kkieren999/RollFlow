# RollFlow V3.7 staff access staging

One sign-in at / routes authorised staff to their workspace, legacy teachers to teaching and administrators to management. The old administrator sign-in remains for compatibility. Administrators can assign multiple named or custom read-only grants through Roles & Permissions. Existing accounts are not automatically granted new access. Admin and teaching permissions remain separate.

Each grant explicitly specifies module(s) and scope. HOD grants require a faculty; Head of Year grants require a year. Faculty scope uses the assigned staff member's faculty (not subject ownership); student directory access is only supported at year or school scope. School-wide grants require explicit administrator action. Scope unions are per module. Existing management endpoints remain admin-only. The grant labels do not confer rights. Changes are logged, and revocation is checked at each request. No public demo identity or imported staff code grants access.

Current modules: read-only staff, student directory, manual classes and manual timetable, plus explicitly granted published OneSchool class and date-specific timetable projections. Published faculty scope requires a current verified binding; year scope excludes unknown/mixed years unless all recorded years are granted. No raw staff codes or roster IDs are returned. Attendance, movements, relief allocation, editing, reusable custom role templates, delegated role management, and complete audit reporting are not implemented here. The public demo already has a unified fictional login and multiple role templates; it must remain fictional and separate. No browser role settings are imported as server grants. No production approval or signed installer is implied.

Before upgrade: back up a staging database and configuration, test migration and rollback on a restored copy, run Django checks and all tests, verify role isolation on Windows with fictional data. Do not use real school records in staging.
