# RC3 ICT deployment runbook — fictional rehearsal only

## Stop/go boundary
RC3 is unsigned synthetic staging. School mode, production startup and real student/staff records are blocked. This runbook is not departmental approval. Do not connect actual OneSchool exports, school credentials or managed production endpoints. Use ICT-approved isolated lab equipment and individually created fictional accounts. The workstation package is an HTTPS browser launcher, not a central server installer; no real school server is supplied.

## Before installation (P01)
1. Record the exact reviewed source commit, successful Actions run including all jobs, version, package filenames and SHA-256 values in the private acceptance record. For pull-request CI record both the branch head and the tested merge checkout SHA; they can differ.
2. Verify installer checksum against independently obtained approved build evidence; unsigned checksums detect corruption, not publisher trust. Never override endpoint protection or trust prompts to install. Obtain ICT permission for the unsigned lab binary.
3. Confirm Windows x64/runtime compatibility, sufficient local NTFS storage, isolated network, restricted dedicated standard account, approved encrypted backup location, and port availability. Do not share state or run database on a network share.
4. Keep old installation and state intact. Do not install over a private state directory. Never reuse real records or an existing database whose origin is uncertain.

## Local Lab (P01–P03)
- Install version 5.0.0-rc.3 in a new application folder; run Verify Package and Pilot Readiness before use. For exact checkout verification from PowerShell in the installation folder: `.\python\python.exe -B -m deployment.pilot_readiness --bundle . --expected-commit FULL_SHA --json` (replace FULL_SHA with the reviewed 40-character checkout SHA).
- Start RollFlow opens the protected workspace menu. First Setup Fresh creates the fixed isolated test state %LOCALAPPDATA%\RollFlow-V38-Fresh-Staging and uses DB 55438 / web 18087. Run once only if state does not exist. If it exists, stop and identify its origin; use a new explicit state rather than erasing it.
- For a separate disposable rehearsal state, use the bundled interpreter with `-m deployment.native --state "C:\approved-lab\RC3-test" init --db-port 55439 --web-port 18088`. Choose unused distinct unprivileged ports; substitute an ICT-approved new path. Use `--state` before the subcommand. Start that same state using `start`; browse http://localhost:18088/ for that example. Keep the console open; Ctrl+C to stop. Use unique fictional admin password, never shared credentials.
- Create individual fictional staff, review scopes, import synthetic data through guarded UI, review both membership reports, dated timetable and bindings; publish only reviewed synthetic sources. Verify denial with a separate unauthorised account. Use the separate offline training demo to practise navigation; it is not secure or database-backed.

## Workstation
Install separately on approved isolated equipment. Verify BUILD-INFO.json and hashes, confirm no app/postgres directories. Configure School Server only for an explicitly ICT-approved synthetic HTTPS endpoint, if one exists. Connection Diagnostics validates configuration, not actual availability or security. Do not configure localhost, bypass TLS, expose a database or provide an unapproved URL. Without an approved synthetic endpoint, record workstation connectivity as not assessed. School-mode server remains blocked by design.

## Proposed future central architecture (not executable authorisation)
Managed HTTPS clients → approved TLS reverse proxy/internal DNS → loopback application → loopback PostgreSQL. ICT must approve authentication/MFA, certificate trust, restricted service identity, firewall and proxy header handling, monitoring, encrypted storage, retention, backup/recovery, signed distribution and support. No direct database client access. Obtain independent review and all ten gate approvals on the exact future release before any real pilot.

## Exit
Run P01–P12; preserve privately recorded defects and evidence; stop on identity mismatch, data loss, unexpected access, integrity or recovery issue. Do not downgrade code against migrated data. Retire only disposable lab data according to ICT retention approval. No go-live from RC3.
