# V5.0 RC2.7 — Complete Visual Polish, Accessibility and Performance Optimisation

Cumulative from RC2.6 commit 58ce75b7b4cf305aa69e681679f37ac595e47a07. Protected Windows application, unsigned fictional staging only. No schema or authority changes. Public Pages remains the pinned visual reference and is not modified.

## Interface and accessibility
- Shared protected CSS: consistent card surfaces, typography, readable form boundaries, 44 px action controls, clear focus indicators, selected attendance outlines, light/dark form and tile improvements, forced-colour treatment and narrow-screen reflow.
- Mobile navigation opens from the keyboard, transfers focus to the active navigation link, closes on Escape or leaving the disclosure, and restores focus on Escape. Account menu has an explicit accessible name; skip links focus the main landmark. The mobile menu offset follows the actual header height.
- Wide data tables get local horizontal scrolling and a named keyboard-reachable region when overflowing; existing wrappers and native table/form elements remain. No JavaScript is needed for the original select-based attendance submission.
- Attendance totals are exposed as a polite live region; column headers use scope attributes. Attendance buttons and native selects remain synchronised, with no parallel submission API.

## Performance
- Attendance marking uses a single delegated form handler and incrementally updates the changed row and four totals; initialization, reset and page restoration rebuild the state. Previously each change scanned all attendance rows.
- The live page renderer reuses its freshly computed navigation presentation snapshot within the same render, including dashboard rendering, rather than recalculating it in the context processor. Never used to authorise an endpoint or write; no global/session caching of grants, records or permissions.
- No new external runtime dependencies. No fabricated percentage or production-scale benchmark.
