# RollFlow V3.6.7 — whole-portal interface audit

## Shared design contract

All server-rendered staff-facing pages use `templates/ui_system.html` for the
same navy (#112332), green (#147f38), neutral surfaces, typography, form
controls, table headings, status messages, focus indicators and responsive
spacing. Standalone pages use `ui_header.html` with role-limited navigation
and POST-only CSRF-protected sign-out. Admin console tabs retain their
existing sidebar but adopt the same tokens, contrast and keyboard landmarks.

The offline legacy teacher demonstration is a single 350 KB `index.html`
application and cannot include Django templates. Its existing fictional
attendance features and navigation are preserved; its tokens and keyboard
focus styles are aligned separately. It must never be mistaken for a live
server-backed roll-marking system.

The teacher header deliberately **does not** offer the admin master timetable,
student directory, staff management or OneSchool imports.

## Visual and interaction QA checklist (manual, before school deployment)

Use an isolated fictional-data instance and test **each** route at
375 px, 768 px and 1366 px (also 200% browser zoom). Confirm:
- Navigation is legible; on narrow screens, it scrolls instead of clipping.
- Every visible action reaches the expected screen; no mixed
  Teacher/Admin access or admin-only student data is exposed to teachers.
- Current tab is indicated with `aria-current`, keyboard tab order works,
  focus rings are visible, and the skip link reaches main content.
- Long names, subject codes and empty directories do not force the page wider
  than the viewport; table regions scroll horizontally.
- Form errors remain visible after server validation; raw CSV editing remains
  available when JavaScript is disabled or a suggestion is rejected.
- Logout is POST/CSRF protected and no page uses GET to sign out.
- Lesson-time grid handles 20 periods and keeps time changes in the existing
  server-side PublishForm; term bounds and staff mapping rules are unchanged.
- A teacher mapped to a published class sees only their own roster and day/week;
  an unmapped teacher sees an explanatory empty state.
- Repeated publish, archive download, class membership, staff activation and
  local backup do not regress.
- Browser print, high contrast, screen reader labels and real tablet devices
  still require supervised evaluation; CI does not take pixel screenshots.

## Deliberately unchanged

No migrations, new privileges, published snapshot replacement, archive
purging, autogenerated new identities or fake live attendance. No student or
staff personally identifiable data is used in tests. The future attendance
and other placeholder features are **not** made operational by a visual audit.

The V3.6.7 PR remains draft and targets the V3.6.6 branch. Main is unchanged.
